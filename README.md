# zkID: Privacy-First Identity Verification

Prove you are 18 or older without revealing your birth year.
Academic prototype. Ethereum Sepolia testnet only. Not a production KYC service.

## What is already built and tested

- circuits/AgeCheck.circom compiled (88 constraints).
- Groth16 keys generated with a local dev ceremony.
- contracts/Verifier.sol generated by snarkjs from the real verification key.
- contracts/zkKYC.sol compiled with solc 0.8.26 with 0 errors.
- 7 local proof tests pass (npm test).

## What is NOT done yet (you must do it)

- Deploy to Sepolia. I cannot do this for you. It needs your MetaMask.
- Browser test with MetaMask. Not run.
- zkKYC.sol was compiled but not executed on an EVM. Test it on Sepolia as described below.

## How it works

Private input: birthYear.
Public inputs: currentYear, ageLimit.
Public output: isAboveLimit.

Circuit rules:
- birthYear is at least 1900.
- birthYear is not after currentYear.
- isAboveLimit is 1 when birthYear + ageLimit <= currentYear.

Public signal order sent to the contract: [isAboveLimit, currentYear, ageLimit].

Contract rules in verifyAge:
- isAboveLimit must be 1.
- ageLimit must be at least 18.
- currentYear must match the chain year, within 1 year.
- The proof must pass the Groth16 verifier.
- The same proof from the same wallet cannot be used twice.
- Only msg.sender gets marked verified. Nobody can verify another wallet.

Age uses year only. Someone born in December 2008 passes in January 2026. This is a known simplification.

## Trust limits (read before your viva)

- A proof shows a statement is true for the input. It does not show the input is real.
- Here you type your own birth year. That is a simulated identity source.
- A real KYC system needs a trusted issuer, such as a government. The issuer signs the birth year. The circuit checks that signature. Without it, anyone can type any year.
- The trusted setup here is a local dev ceremony by one person. A real system needs a public multi-party ceremony.

## Privacy limits

Public on chain:
- Your wallet address.
- The proof and the 3 public signals.
- The time of verification.
- The fact that this wallet passed.

Private:
- Birth year.
- Name and documents (never used).

Your wallet address links all your records. Use a fresh wallet if you want separation.

## Windows setup

You need Node.js 20 or newer. Check with:

```
node -v
```

If missing, install the LTS version from https://nodejs.org.

Open Cursor. Choose File, Open Folder, pick the zkID folder. Open the terminal with Ctrl+backtick (PowerShell is fine).

Install packages:

```
npm install
```

Run the proof tests:

```
npm test
```

Expected: 5 PASS lines for valid, tampered, altered, underage, boundary, plus 2 more PASS lines for impossible years. The "Error in template" lines are normal. They show the circuit refused bad input.

WSL is not needed. Ignore your old WSL files.

## Rebuild the circuit (only if you change the circuit)

Circom 2 runs through npm here as circom2. No Rust install needed.

```
npm run build:circuit
```

This runs scripts/rebuild.sh. On Windows run it in Git Bash or WSL. If you do not change the circuit, skip this. The files are already in place.

After a rebuild the verifier changes. You must redeploy Verifier.sol and zkKYC.sol.

## Run the frontend

```
npm start
```

Open http://localhost:8080 in Chrome with MetaMask installed.

Do not double-click index.html. Browsers block the wasm and zkey files from file:// pages.

1. Open MetaMask. Pick the Sepolia network. Turn on "Show test networks" in settings if needed.
2. Use a Sepolia faucet. Search "Sepolia faucet". Known ones include the Google Cloud Web3 faucet and the Alchemy faucet.

## Deploy with Remix

1. Open https://remix.ethereum.org.
2. In File Explorer create contracts/Verifier.sol. Paste the full contents of zkID/contracts/Verifier.sol.
3. Create contracts/zkKYC.sol. Paste the full contents of zkID/contracts/zkKYC.sol.
4. Open Solidity Compiler. Pick version 0.8.26 (any 0.8.20 or newer works). Turn on Optimization, 200 runs.
5. Click Compile Verifier.sol. Then compile zkKYC.sol. Both must show a green check.
6. Open Deploy and Run. Set Environment to "Injected Provider - MetaMask". Approve the connection.
7. Check the network label shows Sepolia (11155111).
8. Pick contract Groth16Verifier. Click Deploy. Confirm in MetaMask.
9. Copy the deployed address from "Deployed Contracts". This is the verifier address.
10. Pick contract zkKYC. Paste the verifier address in the constructor field. Click Deploy. Confirm in MetaMask.
11. Copy the zkKYC address.

Order: Verifier first, zkKYC second. zkKYC stores the verifier address in its constructor.

Remix cannot compile circuits or make proofs. Use the npm steps above for that.

Check each deployment on https://sepolia.etherscan.io. Paste the address or tx hash. Status must show Success.

## Test plan

|---|---|---|
| Valid proof | Birth year 2000, generate, verify | Tx succeeds. Status Verified on-chain. |
| Invalid proof | Run npm test (tampered proof test) | Rejected locally. |
| Invalid proof on chain | In Remix, call verifyAge on zkKYC with a changed pA value | Revert: Invalid zero-knowledge proof |

| Impossible year | Birth year 1850 or a future year | Page blocks input or circuit refuses. |

| Failed transaction | Reject in MetaMask | "You rejected the request." No success shown. |
| Replay | Submit the same proof twice | Revert: Proof already used |

Success shows only after the transaction is mined and isVerified returns true.

## Common errors

- "Failed to fetch" for wasm or zkey: you opened the file directly. Use npm start.
- "Proof does not match chain year": your PC clock is wrong. Fix the date.
- "insufficient funds": get more Sepolia ETH.
- Remix deploy goes to the wrong chain: the Environment is not Injected Provider.
- "Verifier is not a contract": wrong address in the zkKYC constructor.
- npm install is slow: retry. The registry can be slow.

## Large key files

This circuit is small. The zkey is 46 KB. Real circuits can reach hundreds of MB.
- Do not commit big keys to git. Use Git LFS or a CDN.
- Serve with gzip or brotli and long cache headers.
- Pin a hash of the zkey in your page and check it before use.
- Only the verification key and Verifier.sol need to be trusted public data. The proving key being public is fine.

## Serve securely

- Use HTTPS in any real deployment.
- Add a Content-Security-Policy header.
- Self-host snarkjs (done here in frontend/vendor). ethers loads from jsdelivr. Self-host it too for production.
- Never log birth year. Never send it to a server.

## Architecture

```
Browser (birthYear stays here)
  |  snarkjs fullProve with AgeCheck.wasm + zkey
  v
Proof + public signals [1, year, 18]
  |  ethers v6 + MetaMask
  v
zkKYC.verifyAge  --->  Groth16Verifier.verifyProof (pairing check)
  |
  v
Record: verified flag, time, year, count. Event AgeVerified.
```
